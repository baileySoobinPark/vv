  ## Get Database Encryption Key API
    This API provides an optional mechanism for securely managing the symmetric key used to encrypt data in the Enclave database. Instead of storing PII like sensitive data in plain text, the Enclave encrypts it using symmetric key encryption before storing it to the database. The symmetric key used for encryption must be generated by your VASP and configured as an environment variable for the Enclave. However, exposing the encryption key directly in the environment file poses a security threat.
    To address this, it is recommended to use a reference value—such as an encrypted encryption key, key ID, or resource name—in the environment variable instead of the actual encryption key. 

    By implementing this API and providing its endpoint, the Enclave can use the reference value to securely retrieve or decrypt the actual key at runtime, loading it into memory only when needed. This approach ensures that the encryption key remains protected while maintaining secure access for the Enclave.

  ## How Enclave works
    When `VEGA_ENCRYPTION_KEY_BASE64` environment variable is set and `VEGA_DECRYPT_API_ENDPOINT` is not set,

    Enclave loads the DB encryption key from the `VEGA_ENCRYPTION_KEY_BASE64` environment as it is, and use the key to encrypt sensitive data before storing.

    When `VEGA_ENCRYPTION_KEY_BASE64` environment variable is set and `VEGA_DECRYPT_API_ENDPOINT` is also set,

    The Enclave retrieves the reference value from the `VEGA_ENCRYPTION_KEY_BASE64` environment variable and calls this API, available at the `VEGA_DECRYPT_API_ENDPOINT`, to retrieve the exact encryption key.

    When calling this API, the Enclave sets the inputKey field in the request body to the reference value.

    Upon receiving the response, the Enclave uses the value of outputKey to encrypt sensitive data.

  ## Functional Requirements
    ### 1. Non-API Requirements: Key Generation & Management
      Your VASP must generate an symmetric encryption key for database encryption and prepare a secure mechanism to manage it. This can include using own encryption module, or leveraging a Key Management System (KMS).

    ### 2. API Requirements
    The API must use the reference value received in the inputKey field of the request to retrieve the actual encryption key. This process can involve either decrypting an encrypted key represented by the reference value or using the reference value (e.g., a key indicator) to securely fetch the key from a Key Management System (KMS) or other secure source.

    Once the actual encryption key is retrieved, the API must return it in the outputKey field of the response. This key will be used by the Enclave for database encryption.

    ## Recommendations
    Avoid configuring the database encryption key in plain text directly in the `VEGA_ENCRYPTION_KEY_BASE64` environment variable, as it poses significant security risks.

    It is strongly recommended to integrate a third-party key management service (KMS) to handle key management securely and implement the API.

      For example, when using a service like AWS KMS, you can set `VEGA_ENCRYPTION_KEY_BASE64` to the AWS ARN of the encryption key. 

      Then, configure `VEGA_DECRYPT_API_ENDPOINT` to point to a server that wraps AWS KMS. This server can retrieve the encryption key from AWS KMS using the ARN and provide it for decryption purposes.

    ## Environment Variable Configuration
      Set the following environment variables as per the guide to integrate the implemented API with the Enclave. For a complete list of Enclave environment variables, click here.

        - `VEGA_DECRYPT_API_ENDPOINT`: Implement this API at the desired path({VASP_DEFINED_PATH_DECRYPT_DB_ENCKEY}) and set the path in the variable.

        - `VEGA_ENCRYPTION_KEY_BASE64`: Set the reference value for encryption key to this variable.
