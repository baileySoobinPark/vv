> 💡 테스트 환경 제약사항
>
> 입금 테스트는 **Ethereum Sepolia** , **Ethereum Holesky** 및 **Ripple Testnet**에서만 수행 가능합니다. 테스트를 시작하기에 앞서, 해당 환경에서 자산 전송 테스트가 가능한지 여부와 VASP 입금 지갑 주소 등 필요한 정보를 미리 확인하십시오.

## 개요

입금 시나리오 테스트는 규제 준수 의무가 있는 VASP와의 가상 자산 송수신 상황을 가정한 사전 검증 입금 테스트, 규제 준수 의무가 없는 VASP에게 가상 자산을 수신한 상황을 가정한 사후 검증 입금 테스트가 있습니다. 각 시나리오에 대한 테스트를 진행해 귀사의 VASP가 구현한 VerifyName 프로토콜의 동작 여부를 확인하십시오.

<br />

## 사전 검증 입금 시나리오 테스트 순서

### 2. Report Owner Verification Test

* **조건**

  * Report Verification Simulation API를 호출해 RobotVASP가 최종 검증 결과를 보고하도록 명령합니다.
  * 최종 결과를 보고하지 않은 경우, 다음 단계를 진행할 수 없습니다.

<Accordion title="Report Verification Simulation API 예제" icon="fa-info-circle">
  **Method**: `POST`

  * * **Endpoint**: `//<RobotVASP URL>/vega/robot/v2.0/action/owner-verifications/{request_id}/result`
    * **요청 body 예제**

      * 추가적인 Body 예시는 Enclave API 중 [Report Verification Result API]()  API 문서에서 확인할 수 있습니다.

      ```json
      {
        "verification_result": "VERIFIED"
      }
      ```
      ```json
      {
        "verification_result": "DENIED",
        "reason": "MISMATCH-ADDRESS",
        "message": "mismatch address"
      }
      ```
      ```json
      {
        "verification_result": "ERROR",
        "reason": "TRANSFER-ERROR",
        "message": "test error"
      }
      ```
    * **결과 예제**
      ```json
      {
        "result": true
      }
      ```
</Accordion>

<br />

* **기대 결과**
  * 귀사의 VASP가 구현한 Callback API에 의해 RobotVASP가 보고한 최종 검증 결과가 전달됩니다.
  * callback의 타입이 `OWNER_VERIFICATION_RESULT_REPORT` 인지 확인합니다.

### 3. 온체인 전송 트랜잭션 실행 Test

**Case 1. 트랜잭션 실행 후 트랜잭션 ID(트랜잭션 Hash) 보고**

* **조건**
  * Robot Withdrawal API를 호출할 때, 요청 body의 `omit_tx_report` 필드를 false로 설정하여 호출한 경우, 트랜잭션 ID(트랜잭션 Hash)를 자동으로 보고합니다.
  <br />

* **기대 결과**
  * 귀사의 VASP가 구현한 Callback API를 통해 트랜잭션 ID(트랜잭션 Hash)가 전달됩니다.
  * callbackType이 `OWNER_VERIFICATION_TX_REPORT`인지 확인합니다.
    * 입금 반영에는 최대 20분이 소요될 수 있습니다.
  <br />

**Case 2. 트랜잭션 실행 후 트랜잭션 ID(트랜잭션 Hash) 미보고**

* **조건**

  * Robot Withdrawal API를 호출할 때, 요청 body의 `omit_tx_report` 필드를 true로 설정하여 호출한 경우, RobotVASP가 트랜잭션 ID(트랜잭션 Hash)를 보고하지 않습니다.
  * Check Transaction Status API를 호출해 RobotVASP에게 트랜잭션 상태 확인을 요청합니다.

  <Accordion title="Check Transaction Status API 예제" icon="fa-info-circle">
    **Method**: `POST`

    * * **Endpoint**: `/v2/owner-verifications/{request_id}/tx/inquiry`
      * **요청 body 예제**

        * 추가적인 예시는 Enclave API 중 [Check Transaction Status API]()  API 문서에서 확인할 수 있습니다.

        ```json
        {
            "request_id": "ecbacf57-f813-4670-934a-5c4537fec869"
        }
        ```
      * **결과 예제**
        ```json
        {
          "transaction_status": "CONFIRMED",
          "request_id": "ecbacf57-f813-4670-934a-5c4537fec869",
          "reported_result": "VERIFIED",
          "ordered_at": "2025-04-22T08:35:24.760Z",
          "tx_hash": "0x6CED59A8D2dA7bdf3E6c2920F632421A8f3c34D2"
        }
        ```
  </Accordion>
* 요청 body의 `omit_tx_report` 필드를 true로 설정하여 Check Transaction Status API를 테스트 한 후, Callback API를 테스트하고 싶은 경우, Report Transaction Result Simulation API를 호출해 RobotVASP가 트랜잭션 ID(트랜잭션 Hash)를 보고하도록 명령할 수 있습니다.

    * **RobotVasp SG**: [https://api.verifyvasp.xyz/vega/robot](https://api.verifyvasp.xyz/vega/robot)
