> 💡 테스트 환경 제약사항
>
> 출금 테스트는 **Ethereum Sepolia** , **Ethereum Holesky** 및 **Ripple Testnet**에서만 수행 가능하며 환경별로 허용된 네트워크에서 실행해야 합니다. 테스트를 시작하기에 앞서, 해당 환경에서 자산 전송 테스트가 가능한지 여부와 VASP 출금 지갑 주소 등 필요한 정보를 미리 확인하십시오.

<br />

## 개요

출금 시나리오는 귀사 VASP의 규제 준수 여부에 따라 사전 검증, 사후 검증 두 가지 케이스로 구분합니다. 귀사의 VASP가 규제를 준수하여 자산을 전송하기 전 수신자를 확인해야 하는 의무가 있는 VASP라면 사전 검증 출금 시나리오를, 규제를 준수할 의무가 없는 VASP라면 사후 검증 출금 시나리오를 진행하십시오.

## 사전 검증 출금 시나리오 테스트 순서

사전 검증 출금 시나리오 테스트는 규제 준수 의무가 있는 VASP가 가상 자산을 전송하기 전, 상대 VASP에게 수신인을 검증하는 테스트 입니다. 본 시나리오에서는 귀사의 VASP를 규제 준수 의무가 있는 VASP로 가정합니다.

## 테스트 케이스

* **조건**
  * STG Endpoint로 구동한 Enclave API 중 [List VASP API](ref:travelrule-list-vasp-ids-1)를 호출하여 Robot VASP 정보를 조회합니다.
  <br />
* **기대 결과**
  * API 호출 응답에서 Robot VASP 정보를 확인할 수 있습니다. (vaspId 포함)

* **조건**

  * 귀사의 VASP가 Robot VASP에게 Owner Verification을 요청합니다.
  * Owner Verification의 타입은 `VerifyBeneficiary` 로 설정해야 합니다.

### 3. Report Verification Result Test

**Case 1. 최종 검증 결과 보고 시나리오**

* **조건**

  * 귀사의 VASP가 Owner Verification을 진행해 반환받은 결과를 기반으로 최종 검증 결과를 확정해 보고하는 경우입니다.
  * Enclave API 중 [Report Verification Result API]()을 호출하여 보고합니다.

  <br />

  <Accordion title="Report Verification Result API 예제" icon="fa-info-circle">
    **Method**: `POST`

    * * **Endpoint**: `/v2/owner-verifications/{request_id}/result`
      * **요청 body 예제**

        * 추가적인 예시는 Enclave API 중 [Report Verification Result API]()  API 문서에서 확인할 수 있습니다.

        ```json
        {
          "verification_result": "VERIFIED"
        }
        ```
        ```json
        {
          "verification_result": "DENIED",
          "reason": "MISMATCH-ADDRESS",
          "message": "mismatch address"
        }
        ```
        ```json
        {
          "verification_result": "ERROR",
          "reason": "TRANSFER-ERROR",
          "message": "test error"
        }
        ```
      * **결과 예제**
        ```json
        {
          "result": true
        }
        ```
  </Accordion>

<br />

* **기대 결과**
  * RobotVASP에게 최종 검증 결과를 공유합니다.
  * RobotVASP가 귀사의 VASP에게 최종 검증 결과 문의를 위한 Check Transaction Status API를 호출하지 않습니다.
  <br />

**Case 2. 최종 검증 결과 미보고 시나리오**

* **조건**
  * 귀사의 VASP가 Owner Verification 진행 이후 최종 검증 결과를 보고하지 않는 경우입니다.
  <br />
* **기대 결과**
  * 결과를 보고하지 않고 10분이 경과한 시점부터 RobotVASP가 귀사의 VASP에게 Transaction Status를 확인하는 요청을 전송합니다. (1시간이 경과할 때 까지 주기적으로 호출합니다.)
    * 미보고 시 다음 단계를 진행할 수 없으므로 귀사의 VASP가 구현한 VASP API 중 Check Transaction Status API의 동작을 확인했다면 최종 검증 결과를 보고해야 다음 단계를 진행할 수 있습니다.
  <br />

### 4. 온체인 전송 트랜잭션 실행 Test

> ❗️ 주의 사항:
>
> XRP 주소로 테스트를 진행할 때에는 반드시 destination tag를 포함해 주십시오. destination tag를 포함하는 방법은 [IVMS101 가이드]() 에서 확인할 수 있습니다.

가상 자산을 전송하기 전, 입금 확인을 위해 Balance Check API를 호출해 수신인 지갑 주소의 현재 잔액을 확인합니다.

</Accordion>

**Case 1. 트랜잭션 실행 후 트랜잭션 ID(트랜잭션 Hash) 보고**

* **조건**
  * 온체인에서 가상 자산 전송 트랜잭션을 실행합니다.
  * Enclave API 중 [Report Transaction Result API]() 를 호출하여 트랜잭션 결과를 보고합니다.

    <br />

    <Accordion title="Report Transaction Result API 예제" icon="fa-info-circle">
      **Method**: `POST`

      * **Endpoint**: `/v2/owner-verifications/{request_id}/tx`
      * **요청 body 예제**
        * 추가적인 예시는 Enclave API 중 [Report Transaction Result API]()  API 문서에서 확인할 수 있습니다.

          ```json
          {
            "tx_hash": "0xbdd6e9e12514507cee06e31dd4a64acb0777f2365902ee9577c656322f9f2f74"
          }
          ```
        * **결과 예제**
          ```json
          {
            "result": true
          }
          ```
    </Accordion>

<br />

* **기대 결과**
  * Check Balance API를 다시 호출해 가상 자산이 Robot VASP에 입금된 것을 확인할 수 있습니다.
    * 입금 반영에는 최대 20분이 소요될 수 있습니다.

## 테스트 케이스

### 1. 수신인의 현재 자산 확인 Test

* **조건**
  * 가상 자산을 전송하기 전, RobotVASP가 관리하는 수신인 지갑 주소의 잔액을 확인합니다. 가상 자산 전송 트랜잭션을 실행한 후 잔액을 확인하여 자산이 전송된 것을 명확하게 확인할 수 있습니다.

<Accordion title=" Check Balance API 예제" icon="fa-info-circle">
  **Method**: `GET`

  * **Endpoint**: `<VASP URL>/vega/robot/v1.0/testnet/balance`
  * **RobotVasp KR URL**: [https://api-kr.verifyvasp.xyz/vega/robot](https://api-kr.verifyvasp.xyz/vega/robot)
  * **RobotVasp SG URL**: [https://api.verifyvasp.xyz/vega/robot](https://api.verifyvasp.xyz/vega/robot)
  * **요청 쿼리 파라미터**

  | Parameter Name | Type   | Description   | Example                                    |
  | -------------- | ------ | ------------- | ------------------------------------------ |
  | `vaspId`       | string | 송신인 VASP의 ID  | 15952089931162058999                       |
  | `symbol`       | string | 전송된 가상 자산의 심볼 | ETH                                        |
  | `address`      | string | 가상 자산을 수신할 주소 | 0xb0bFf9721871e22653358956cf59a5FdBF3D752F |

  * **요청 예제**

    ```
    <https://api.verifyvasp.xyz/vega/robot/v1.0/testnet/balance?vaspId=15952089931162058999&symbol=ETH&address=0xb0bFf9721871e22653358956cf59a5FdBF3D752F>
    ```

    ```json
        "symbol": "ETH",
    ```

### 4. Report Verification Result Test

* **조건**

  * Report Verification Result Simulation API를 호출해 RobotVASP가 최종 검증 결과를 보고하도록 명령합니다.

<Accordion title="Report Verification Result Simulation API 예제" icon="fa-info-circle">
  **Method**: `POST`

  * **Endpoint**: `//<Robot VASP URL>/vega/robot/v2.0/action/owner-verifications/{request_id}/result`
  * **요청 body 예제**
    * 추가적인 예시는 Enclave API 중 [Report Verification Result API]()  API 문서에서 확인할 수 있습니다.

      ```json
      {
          "verification_result": "VERIFIED"
      }
      ```
      ```json
      {
      "verification_result": "DENIED",
      "reason": "MISMATCH-ADDRESS",
      "message": "mismatch address"
      }
      ```
      ```json
      {
      "verification_result": "ERROR",
      "reason": "TRANSFER-ERROR",
      "message": "test error"
      }
      ```
    * **결과 예제**
      ```json
        {
            "result": true
          }
      ```
</Accordion>

<br />

* **기대 결과**
  * RobotVASP가 보고한 최종 검증 결과를 귀사의 VASP가 Callback API를 통해 확인할 수 있습니다.
  * callbackType이 `OWNER_VERIFICATION_RESULT_REPORT` 으로 설정되어 있습니다.
