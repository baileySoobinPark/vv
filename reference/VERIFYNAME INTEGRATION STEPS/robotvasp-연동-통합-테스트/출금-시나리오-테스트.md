> 💡 테스트 환경 제약사항
>
> 출금 테스트는 **Ethereum Sepolia** , **Ethereum Holesky** 및 **Ripple Testnet**에서만 수행 가능합니다. 테스트를 시작하기에 앞서, 해당 환경에서 자산 전송 테스트가 가능한지 여부와 VASP 출금 지갑 주소 등 필요한 정보를 미리 확인하십시오.

<br />

## 개요

출금 시나리오는 귀사 VASP의 규제 준수 여부에 따라 사전 검증, 사후 검증 두 가지 케이스로 구분합니다. 귀사의 VASP가 규제를 준수하여 자산을 전송하기 전 수신자를 확인해야하는 의무가 있는 VASP라면 사전 검증 출금 시나리오를, 규제를 준수할 의무가 없는 VASP라면 사후 검증 출금 시나리오를 진행하십시오.

## 사전 검증 출금 시나리오 테스트 순서

사전 검증 출금 시나리오 테스트는 귀사의 VASP와 Robot VASP 모두 규제 준수 의무가 있는 VASP인 경우를 가정한 상황의 테스트 입니다. 다음과 같은 순서로 진행됩니다.

### 3. Report Verification Result Test

**Case 1. 최종 검증 결과 보고 시나리오**

* **조건**
  * 귀사의 VASP가 Owner Verification을 진행해 반환받은 결과를 기반으로 최종 검증 결과를 확정해 보고합니다.
  * 원활한 테스트 진행을 위해 Owner Verification의 결과를 `VERIFIED`라고 판단하고 보고해야 합니다.
  * Enclave API 중 [Report Verification Result API]()을 호출하여 테스트합니다.
  * <Accordion title="Report Verification Result API 예제" icon="fa-info-circle">
      **Method**: `POST`

      * * **Endpoint**: `/v2/owner-verifications/{request_id}/result`
        * **요청 body 예제**

          * 추가적인 Body 예시는 Enclave API 중 [Report Verification Result API]()  API 문서에서 확인할 수 있습니다.

          ```json
          {
            "verification_result": "VERIFIED"
          }
          ```
    </Accordion>

<br />

* **기대 결과**
* 정상 검증(`VERIFIED`) 케이스의 경우, 아래의 값을 반환받을 수 있습니다.
  ```
  {
  	"result": true
  }
  ```
  <br />
* 비정상 검증(`DENIED`) 케이스의 경우, 사유 코드가 반환되는지 확인합니다. 예를 들어, 테스트 데이터 외의 임의의 데이터로 검증을 요청하여 `UNKNOWN-ADDRESS`가 발생하는지 확인할 수 있습니다.
  * `VERIFIED`
  * `UNKNOWN-SYMBOL`
  * `UNKNOWN-ADDRESS`
  * `UNVERIFIED-KYC`
  * `MISMATCHED-NAME`
  * `UNAVAILABLE-INFORMATION`
  * `LACK-OF-INFORMATIONBLACKLISTED`

<br />

**Case 2. 최종 검증 결과 미보고 시나리오**

* **조건**
  * 귀사의 VASP가 Owner Verification을 진행해 반환받은 결과를 기반으로 확정한 최종 검증 결과를 보고하지 않습니다.
  * 결과를 보고하지 않고 10분 경과한 시점부터 Robot VASP가 귀사의 VASP에게 Transaction Status를 확인하는 요청을 전송합니다. (1시간이 경과할 때 까지 주기적으로 호출합니다.)
  * Robot VASP가 귀사의 VASP가 구현한 Implementation API 중 Check Transaction Status API를 호출하여 검증 결과를 확인합니다.
  <br />
* **기대 결과**
  * Report Verification Result API를 이용해 최종 검증 결과를 보고합니다. 결과가 보고된 후, 검증 결과를 확인하는 API 호출을 정지합니다.

### 4. 온체인 전송 트랜잭션 실행

> 💡 참고 사항:
>
> 최종 검증 결과를 `VERIFIED`로 보고한 경우,  반드시 수신인(Robot VASP가 관리하는 가상의 사용자) 지갑 주소에 가상 자산을 전송해야 합니다. 만약 가상 자산을 전송하지 않거나 `VERIFIED` 응답을 받지 않고 Robot VASP에 가상 자산을 전송할 경우 본 테스트 이후 입금 테스트를 진행할 수 없습니다.
>
> XRP 주소로 테스트를 진행할 때에는 반드시 destination tag를 포함해 주십시오. destination tag를 포함하는 방법은 [IVMS101 가이드]() 에서 확인할 수 있습니다.

가상 자산을 전송하기 전, 명확한 입금 확인을 위해 Balance Check API를 호출해 수신인 지갑 주소의 현재 잔액을 확인합니다.

<Accordion title=" Check Balance API 예제" icon="fa-info-circle">
  **Method**: `GET`

  * **Endpoint**: `<VASP URL>/vega/robot/v1.0/testnet/balance`
  * **RobotVasp KR**: [https://api-kr.verifyvasp.xyz/vega/robot](https://api-kr.verifyvasp.xyz/vega/robot)
    * **RobotVasp SG**: [https://api.verifyvasp.xyz/vega/robot](https://api.verifyvasp.xyz/vega/robot)
  * **요청 쿼리 파라미터**

  | Parameter Name | Type   | Description   | Example                                    |
  | -------------- | ------ | ------------- | ------------------------------------------ |
  | `vaspId`       | string | 송신인 VASP의 ID  | 15952089931162058999                       |
  | `symbol`       | string | 전송된 가상 자산의 심볼 | ETH                                        |
  | `address`      | string | 가상 자산을 수신할 주소 | 0xb0bFf9721871e22653358956cf59a5FdBF3D752F |

  * **요청 예제**

    ```
    <https://api.verifyvasp.xyz/vega/robot/v1.0/testnet/balance?vaspId=15952089931162058999&symbol=ETH&address=0xb0bFf9721871e22653358956cf59a5FdBF3D752F>
    ```

  * **결과 예제**
    ```json
      {
        "symbol": "ETH",
        "address": "0xFa230E9cCAF5e382539147294d7965Eeccbbfa5c",
        "vaspId": "15952089931162058999",
        "value": "0.0497"
    }
    ```
</Accordion>

**Case 1. 트랜잭션 실행 후 트랜잭션 ID(트랜잭션 Hash) 보고**

* **조건**
  * Enclave API 중 [Report Transaction Result API]() 를 호출하여 트랜잭션 결과를 보고합니다.

    <br />

    <Accordion title="Report Transaction Result API 예제" icon="fa-info-circle">
      **Method**: `POST`

      * * **Endpoint**: `/v2/owner-verifications/{request_id}/tx`
        * **요청 body 예제**

          * 추가적인 Body 예시는 Enclave API 중 [Report Transaction Result API]()  API 문서에서 확인할 수 있습니다.

          ```json
          {
            "tx_hash": "0xbdd6e9e12514507cee06e31dd4a64acb0777f2365902ee9577c656322f9f2f74"
          }
          ```
      * **결과 예제**
        ```json
        {
          "result": true
        }
        ```
    </Accordion>

<br />

* **기대 결과**
  * Check Balance API를 다시 호출해 가상 자산이 Robot VASP에 입금된 것을 확인할 수 있습니다.
  * 입금 반영에는 최대 20분이 소요될 수 있습니다.

<br />

**Case 2. 트랜잭션 실행 후 트랜잭션 ID(트랜잭션 Hash) 미보고**

* **조건**

  * 귀사의 VASP가 가상 자산 전송 트랜잭션을 실행하고 반환받은 트랜잭션 ID(트랜잭션 Hash)를 보고하지 않습니다.
  * 결과를 보고하지 않고 10분 경과한 시점부터 Robot VASP가 귀사의 VASP에게 Transaction Status를 확인하는 요청을 전송합니다. (1시간이 경과할 때 까지 주기적으로 호출합니다.)
* **기대 결과**
  * Report Transaction Result API를 이용해 트랜잭션 실행 결과를 보고합니다. 결과가 보고된 후, Robot VASP가 Transaction 상태를 확인하는 API 호출을 정지합니다.
  * 트랜잭션 실행 결과를 보고하지 않을 경우, 입금 반영을 확인할 수 없습니다. 그러나 **5. 트랜잭션 실행 후 검증 진행** 단계를 진행하여 송신인을 검증하고 입금 결과를 반영할 수 있습니다.
  <br />
